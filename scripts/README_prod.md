# Скрипты обслуживания прод-версии SolePro Finance Assistant

Эти скрипты предназначены для **боевой (прод) установки** приложения,
где `data/` — символьная ссылка на реальное хранилище базы данных.

## Файлы

| Файл | Назначение |
|------|------------|
| `setup.bat` | Первичная установка на Windows (запускается из корня проекта) |
| `setup.ps1` | Создание `.venv`, установка зависимостей, `.env` и БД |
| `common.ps1` | Общие функции выбора Python и загрузки сообщений |
| `locales/messages.ru.json` | Русские сообщения служебных скриптов |
| `update_prod.bat` | Обновление прод-версии с GitHub (обёртка для `update_prod.ps1`) |
| `update_prod.ps1` | Логика обновления: бэкап → код из GitHub → зависимости |
| `backup_db.ps1` | Ручная резервная копия базы данных |
| `backup_sqlite.py` | Консистентное копирование SQLite и проверка целостности |

## Первичная установка

Из корня проекта запустите:

```
setup.bat
```

Установщик создаёт `.venv`, устанавливает зависимости, создаёт `.env` из
шаблона только при его отсутствии и инициализирует базу. Для разработки:

```
setup.bat -Dev
```

## Первая установка скриптов в прод

Скрипты версионируются в репозитории (`scripts/`). При первом использовании
скопируйте папку `scripts/` (или эти три файла) в корень прод-папки.
В дальнейшем они обновляются автоматически вместе с кодом.

## Обновление прода

> **Перед запуском закройте приложение** (десктоп и Telegram-бот).
> Скрипт проверяет процессы Python из прод-папки и остановит обновление,
> если приложение ещё работает.

Из папки прода:

```
scripts\update_prod.bat
```

Что произойдёт:
1. Консистентная резервная копия SQLite с `integrity_check` → `.backup\db\finances_<версия>_<дата>.db`.
2. Снимок текущей версии (код + конфиг) → `.backup\<версия>_<дата>\`.
3. Загрузка последнего кода из GitHub во временную папку.
4. Установка зависимостей до замены файлов приложения.
5. Синхронизация кода в прод. **НЕ затрагиваются:** `.env`, `settings/`,
   `data` (символьная ссылка), `.backup/`, `.venv/`.
6. Удаление только устаревших файлов из манифеста предыдущей поставки.
7. Обязательное применение миграций и начальных данных через `scripts/init_db.py`.

### Параметры `update_prod.ps1`

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| `-ProdPath` | папка-родитель скрипта | Корень прод-установки |
| `-RepoUrl` | GitHub репозиторий | Источник кода |
| `-Branch` | `main` | Ветка |
| `-SkipDeps` | — | Пропустить установку зависимостей |
| `-Yes` | — | Без интерактивных подтверждений |

Пример (тихий режим):

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\update_prod.ps1 -Yes
```

## Резервная копия базы (отдельно)

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup_db.ps1
```

Оставить только 30 последних копий:

```
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\backup_db.ps1 -Keep 30
```

## Откат к предыдущей версии

Полный снимок прежней версии лежит в `.backup\<версия>_<дата>\`, база —
в `.backup\db\`. Для отката восстановите нужные файлы из снимка и/или базу
из `.backup\db` в `data\`.
