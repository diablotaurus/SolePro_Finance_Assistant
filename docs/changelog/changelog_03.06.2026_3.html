Приоритет 1 — Единая спецификация фильтрации

Логика фильтрации транзакций и нормализации дат была продублирована в четырёх местах. Введён единый immutable-класс TransactionFilterSpecification (паттерн Specification) — единственный источник истины.

Specification

DRY · SOLID

Инкапсулирует правило соответствия (SRP), нормализацию периода и порождение спецификации соседнего периода (for_period). Удалены 4 копии фильтрации и 2 копии нормализации дат.

class TransactionFilterSpecification: def is_satisfied_by(self, tx) -> bool: ... @classmethod def from_filter_dto(cls, dto): ... def for_period(self, start, end): ...
core/application/specifications.py
use_cases: List / Search / статистика (транзакции и контрагенты)

Приоритет 2 — Read-модель против N+1

Имя контрагента уже загружалось через lazy="joined", но Use Cases повторно запрашивали его (get_by_id) на каждого контрагента. Введена read-модель TransactionView, отдающая имя из готового JOIN — без лишних запросов.

TransactionView

PERFORMANCE

Read-модель + методы get_by_id_with_counterparty / find_all_with_counterparty / search_with_counterparty. Построение запросов вынесено в общие хелперы (DRY).

Приоритет 3 — Статистика: загрузка по диапазону дат

Статистика загружала всю таблицу в память. Теперь для статистики за период грузится только окно дат [предыдущий период … конец] через find_by_date_range; агрегация остаётся в Python через тот же Specification.

Приоритет 4 — Деньги контрагента как Decimal

Поле CounterpartyResponseDTO.total_income было float — недопустимо для финансового ПО. Переведено на Decimal сквозным образом: репозиторий → mapper → DTO. На PostgreSQL сохраняется точность SUM(Numeric).

Точность

CORRECTNESS
# DTO total_income: Decimal = Field(Decimal("0"), ...) # mapper / репозиторий Decimal(str(payload.get("total_income", 0)))

Потребители проверены: :,.2f, float(...) и сравнения Decimal == float работают корректно.

Стабильность и гигиена (pydantic + Приоритет 5)

pydantic BaseSettings

STABILITY

Предупреждение от dependency-injector (прощупывал перенесённый pydantic.BaseSettings в pydantic v2) устранено добавлением официального pydantic-settings. Наш код BaseSettings не использует.

Приоритет 5 — Чистка

HYGIENE

3 файла nppBackup/ убраны из индекса git (на диске остались), добавлено правило nppBackup/ в .gitignore. Удалена неиспользуемая зависимость loguru.

Осознанно отложено
