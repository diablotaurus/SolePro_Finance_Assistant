Обзор

Вторая волна исправлений по итогам полного code review: четыре проблемы надёжности и безопасности (приоритет P2). Тестов стало 205 → 215.

1. Telegram-бот: fail-closed вместо fail-open

SECURITY
  • Раньше пустой TELEGRAM_ALLOWED_USERS открывал финансового бота ВСЕМ пользователям Telegram
  • Теперь пустой список = доступ закрыт для всех (fail-closed)
  • Открытый доступ для разработки включается только явно: TELEGRAM_ALLOW_ALL=True
  • При заполненном allowlist флаг не расширяет доступ
  • Бот пишет предупреждение в лог при пустом списке и при включённом открытом доступе
# .env TELEGRAM_ALLOWED_USERS= # пусто -> доступ закрыт (раньше: открыт всем!) # TELEGRAM_ALLOW_ALL=True # открыть всем — только для разработки

2. Money: форматирование без зависимости от локали системы

RELIABILITY
  • str(Money) вызывал locale.setlocale('ru_RU') — на системах без русской локали (типичный Linux) падал locale.Error при любом выводе суммы, включая логирование
  • Теперь str(Money) использует встроенное форматирование: «1 234 567,89 ₽» на любой ОС
  • format(locale_name=...) сохранён, но стал устойчивым: недоступная локаль → фолбэк вместо исключения
  • Исправлено восстановление локали в finally (не падает, если setlocale не удался)

3. Response-DTO не валидирует «дату в будущем»

RELIABILITY
  • TransactionResponseDTO наследовал валидатор «дата не в будущем» — перевод системных часов назад ломал бы чтение уже сохранённых транзакций
  • Валидатор перенесён в TransactionCreateDTO: бизнес-правила ввода проверяются только при создании
  • Доменная сущность по-прежнему валидирует дату при записи

4. SQLite: движок без несовместимых пул-параметров

RELIABILITY
  • pool_size / max_overflow / pool_recycle передаются только сетевым СУБД (PostgreSQL)
  • sqlite:///:memory: больше не падает с TypeError (пул SQLite эти параметры не принимает)
  • Тест подтверждает PRAGMA foreign_keys=ON на каждом SQLite-соединении (из v1.4.19)

Тесты (205 → 215)

  • Middleware: пустой allowlist блокирует; явный allow_all открывает; при заполненном списке флаг игнорируется
  • Money: str() детерминирован на любой системе; фолбэк при недоступной локали (setlocale подменяется — Windows принимает почти любые имена локалей)
  • DTO: response принимает «будущую» дату, create — по-прежнему нет
  • Конфиг: TELEGRAM_ALLOW_ALL по умолчанию False, парсится из env
  • SessionManager: in-memory SQLite работает; PRAGMA foreign_keys=1
