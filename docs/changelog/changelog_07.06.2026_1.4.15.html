Обзор

Исправлены две проблемы в скриптах обновления прод-версии (добавлены в v1.4.14), выявленные при первом запуске на боевой машине: некорректное чтение кириллицы под Windows PowerShell 5.1 и недоступность системных утилит при «урезанном» PATH.

Что исправлено

BUGFIX
ПроблемаБылоСтало
Кириллица в .ps1 ломала парсер UTF-8 без BOM → PS 5.1 читал как cp1251 UTF-8 с BOM
robocopy / chcp «не распознаны» вызов по имени (требует System32 в PATH) вызов по полному пути из %SystemRoot%\System32
Вывод русского текста мог отображаться искажённо [Console]::OutputEncoding = UTF-8
Подтверждение (yes/no) (y/n) — принимает y или yes

Затронутые файлы

scripts/update_prod.ps1 — BOM, robocopy по полному пути, (y/n), UTF-8 вывод
scripts/backup_db.ps1 — BOM, UTF-8 вывод
scripts/update_prod.bat — chcp по полному пути, ASCII-заголовок
pyproject.toml — версия 1.4.15

Примечание по кодировке

UTF-8 BOM здесь — намеренное исключение из правила «без BOM», касающееся только PowerShell-скриптов: Windows PowerShell 5.1 без BOM читает .ps1 в системной ANSI-кодировке (cp1251) и портит кириллицу. Файлы исходного кода (Python и пр.) остаются без BOM.
