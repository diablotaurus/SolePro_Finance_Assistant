Обзор

По итогам полного code review проекта найдены и исправлены три бага, влияющих на корректность данных. Все исправления подтверждены воспроизведением до фикса и регрессионными тестами после (тестов стало 192 → 205).

Баг 1. Фильтр «по дату» терял транзакции, добавленные ботом

BUGFIX
  • Date-пикеры отдают дату без времени; pydantic приводил её к datetime полуночи
  • Нормализация конечной границы «до конца дня» не срабатывала для datetime
  • Транзакции бота (вводятся с реальным временем) выпадали из выборки при фильтре «по: сегодня» — по умолчанию в десктопе
  • Исправление: конечная граница с временем 00:00 трактуется как «весь этот день» (до 23:59:59.999999)
# До: транзакция бота от 10.07 14:30 НЕ проходила фильтр «по 10.07» # После: Транзакция бота 10.07 14:30 проходит фильтр 'по 10.07': True

Баг 2. Удаление контрагента оставляло «висячие» ссылки

BUGFIX
  • В SQLite не был включён PRAGMA foreign_keys — ondelete="SET NULL" не работал; транзакции удалённого контрагента ссылались на несуществующую запись (в топе контрагентов появлялись «сырые» UUID)
  • Включён PRAGMA foreign_keys=ON для всех SQLite-соединений
  • Убран противоречащий cascade="all, delete-orphan" (мина: при переходе на ORM-удаление он бы молча удалил все транзакции контрагента)
  • Репозиторий при удалении явно отвязывает транзакции (SET NULL) — работает независимо от версии схемы БД
  • Новая миграция Alembic 20260716_0003 чистит уже существующие «висячие» ссылки
  • UI предупреждает: «У контрагента N транзакц.: они сохранятся, но останутся без контрагента»

Баг 3. Нельзя было убрать контрагента у транзакции

BUGFIX
  • В TransactionUpdateDTO None означает «не менять» — выбор «-- Выберите контрагента --» при редактировании молча игнорировался
  • Добавлен явный флаг clear_counterparty: DTO → use case → доменная сущность
  • Попутно исправлен репозиторий: merge() не затирал counterparty_id в NULL, т.к. атрибут выставлялся условно
  • Новый counterparty_id, если передан, имеет приоритет над флагом

Попутное исправление: upgrade_database_to_head игнорировал URL

  • alembic/env.py всегда брал URL из конфигурации приложения (.env), затирая явно переданный параметр database_url
  • Теперь явный URL передаётся через config.attributes и имеет приоритет; запуск alembic из CLI работает как раньше

Тесты (192 → 205)

  • Новый модуль test_specifications.py: нормализация границ периода (5 тестов), включая регресс «транзакция бота проходит фильтр date-пикера»
  • test_use_cases_counterparties.py: удаление контрагента сохраняет транзакции и отвязывает их
  • test_use_cases_transactions.py: снятие контрагента флагом + None не трогает контрагента
  • test_domain.py: clear_counterparty в сущности (None ≠ снять; приоритет нового ID)
  • Миграция 20260716_0003 проверена на чистой БД и на БД с «висячей» ссылкой
