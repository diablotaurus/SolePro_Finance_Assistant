Прокси для Telegram-бота с автоматическим обходом при недоступности
Дата: 07.06.2026

Автор: Diablotaurus
Тип: Feature

Обзор

Telegram-бот научился ходить к Telegram через прокси (SOCKS5/HTTP), заданный переменной окружения TELEGRAM_PROXY. Удобно, если прямой доступ к api.telegram.org ограничен: трафик пускается через локальный прокси (например, порт Happ/xray). Если прокси задан, но недоступен (например, Happ выключен), бот автоматически подключается напрямую — без падения.

Что добавлено

FEATURE
  • Новая настройка TELEGRAM_PROXY в .env (по умолчанию пусто = напрямую)
  • Прокси применяется и к API-запросам, и к получению обновлений (long polling)
  • Поддержка SOCKS5 (добавлена зависимость socksio через extra [socks]) и HTTP-прокси
  • «Мягкий» режим: перед стартом проверяется доступность прокси (TCP-подключение к host:port с коротким таймаутом)
  • Прокси недоступен → бот идёт напрямую; в лог пишется предупреждение
# .env # Прокси для Telegram (напр. локальный порт Happ/xray). Пусто = напрямую. TELEGRAM_PROXY=socks5://192.168.0.8:10808

Как работает fallback

  • Функция is_proxy_reachable() парсит URL и пробует TCP-подключение к прокси
  • Порт берётся из URL; если не указан — подставляется дефолт для схемы (socks5 → 1080)
  • Локальный прокси выключен → порт не слушается → мгновенный возврат к прямому соединению
  • Логика чистая и покрыта юнит-тестами (без обращения в интернет)
if proxy_url: if is_proxy_reachable(proxy_url): builder = builder.proxy(proxy_url).get_updates_proxy(proxy_url) # через прокси else: # ⚠️ прокси недоступен — подключение напрямую

Тесты

  • Новый модуль test_telegram_proxy.py: доступность прокси на реально слушающем сокете vs закрытом порту, пустой/битый URL, дефолтный порт, чтение TELEGRAM_PROXY в конфиг
  • test_telegram_bot.py: прокси применяется, когда доступен, и пропускается, когда недоступен
  • Всего тестов: 181 → 192, все проходят
