Причина выпуска

Telegram-бот завершал работу, если первый запрос инициализации к Telegram API попадал на кратковременный сетевой сбой. Диагностика показала ConnectTimeout при недоступном прямом соединении и рабочий запуск через настроенный SOCKS5-прокси после восстановления маршрута.

Дополнительный риск: INFO-журнал библиотеки HTTPX содержал полный URL Telegram API. Такой URL включает токен бота, поэтому служебный HTTP-трафик исключён из INFO-логов.

Устойчивость запуска

Исправлено
  • В существующий вызов Application.run_polling() добавлен параметр bootstrap_retries=-1.
  • При временной ошибке Telegram API бот продолжает попытки инициализации вместо немедленного завершения.
  • Настроенный прокси и текущая логика выбора подключения сохранены без архитектурных изменений.
  • Фоновые сетевые ошибки polling по-прежнему журналируются без повторяющихся уведомлений администратору.

Безопасное журналирование

Безопасность
  • Уровень логгера httpx установлен в WARNING.
  • Уровень низкоуровневого логгера httpcore также установлен в WARNING.
  • Обычные HTTP-запросы, включая URL с токеном, больше не попадают в консоль и logs/bot.log.
  • Предупреждения и ошибки транспортного уровня остаются доступными для диагностики.
Эксплуатационное действие: токен, попавший в старый локальный журнал, необходимо отозвать через BotFather. После выпуска нового токена следует обновить .env и удалить либо безопасно архивировать старый logs/bot.log.

Не связанная с запуском настройка

Для одного значения из TELEGRAM_ALLOWED_USERS Telegram возвращает Chat not found при отправке стартового сообщения. Ошибка обрабатывается и не останавливает бота. Пользователь должен сначала открыть диалог с ботом и выполнить /start, либо неактуальный ID следует удалить из .env.
