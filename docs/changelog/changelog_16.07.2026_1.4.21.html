Обзор

Завершающая волна по итогам полного code review: удалён мёртвый код, устранено тройное дублирование констант валидации, упрощены контракты сигналов диалогов. Поведение приложения не меняется. Тестов: 215 → 212 (убраны тесты, существовавшие только ради мёртвых методов), все проходят.

Удалён мёртвый код

CLEANUP
  • shared/formatters.py и shared/validators.py — пустые модули-заглушки
  • shared/utils.py — неиспользуемый метакласс Singleton
  • DI: незаполняемый providers.Configuration и неиспользуемые провайдеры session_factory / transaction_repository / counterparty_repository
  • Репозиторий транзакций: find_by_counterparty, find_by_type, get_statistics, get_monthly_summary, get_total_income/expense/tax/profit — не использовались в приложении (жили только ради собственных тестов); удалены из интерфейса и реализации (ISP)
  • FilterPanel: пустой обработчик on_filter_changed и 7 подключений сигналов к нему
  • Локальный мусорный каталог nppBackup внутри src (в git не попадал)

DRY: константы бизнес-правил в одном месте

DRY
  • Новый модуль core/domain/constants.py: MAX_MONEY_AMOUNT (1 млрд), MAX_COUNTERPARTY_NAME_LENGTH (200), MAX_NOTE_LENGTH (1000)
  • Используются во всех трёх слоях валидации: доменные сущности (Money, Counterparty), pydantic-DTO, SQLAlchemy-модели
  • Раньше изменение лимита требовало синхронной правки трёх файлов с «магическими» литералами

Упрощены контракты сигналов диалогов

REFACTOR
  • TransactionDialog и CounterpartyDialog при сохранении собирали фиктивный Response-DTO со случайным UUID и датами «сейчас» — потребители использовали из него только ID
  • Теперь сигнал несёт {"transaction_id"/"counterparty_id", "data", "is_edit"} — сохранением занимается контроллер, фиктивных объектов нет

Прочие улучшения

  • Статистика контрагентов (get_statistics): денежные суммы идут в Decimal до самого DTO, без прохода через float — единообразно с миграцией на Decimal (v1.4.5)
  • DesktopUiSettings: корень проекта определяется по маркеру pyproject.toml (устойчиво к переносу файлов); «магический» индекс родителя остался фолбэком
  • Бот подписывается только на message-обновления: обработчиков callback_query/inline_query нет
