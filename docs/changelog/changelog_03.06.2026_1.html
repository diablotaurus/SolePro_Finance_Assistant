Изменений API Use Cases

Приоритет 1 — Единая спецификация фильтрации (DRY/SOLID)

Логика фильтрации транзакций (даты, тип, налог, диапазон суммы, контрагент) и нормализации дат была продублирована в четырёх местах. Введён единый immutable-класс TransactionFilterSpecification (паттерн Specification) — единственный источник истины для правила фильтрации.

TransactionFilterSpecification

APPLICATION

Инкапсулирует правило соответствия транзакции активным фильтрам (SRP), нормализацию начала/конца периода и порождение спецификации для соседнего периода (for_period) для сравнения периодов в статистике.

class TransactionFilterSpecification: def is_satisfied_by(self, transaction: Transaction) -> bool: if self._start_dt and transaction.date < self._start_dt: return False if self._end_dt and transaction.date > self._end_dt: return False # ... тип, налог, диапазон суммы, контрагент return True @classmethod def from_filter_dto(cls, filter_dto): ... def for_period(self, start, end): ...

Устранённое дублирование

DRY

Четыре копии фильтрации и две копии нормализации дат заменены на единый вызов spec.is_satisfied_by(...). Удалены приватные методы _matches_filters, _matches_transaction_filters, _to_start_datetime, _to_end_datetime.

ListTransactionsUseCase — фильтрация через spec
SearchTransactionsUseCase — фильтрация через spec
GetTransactionStatisticsUseCase — spec + for_period
GetCounterpartyStatisticsUseCase — from_filter_dto

Приоритет 2 — Read-модель против N+1 запросов

Связь TransactionModel.counterparty уже загружается через lazy="joined", однако доменная сущность хранит только counterparty_id, поэтому Use Cases повторно запрашивали имя контрагента (get_by_id) — по запросу на каждого уникального контрагента. Введена лёгкая read-модель TransactionView, отдающая имя из уже загруженного JOIN — без дополнительных запросов. Доменная сущность Transaction осталась «чистой».

Read-модель TransactionView

DOMAIN · CONTRACT

Immutable read-модель в контракте репозитория. Реализация мапит имя из уже загруженной связи, не обращаясь к БД повторно.

@dataclass(frozen=True) class TransactionView: transaction: Transaction counterparty_name: Optional[str] = None # Реализация: имя берётся из уже загруженного JOIN def _to_view(self, model): name = model.counterparty.name if model.counterparty else None return TransactionView(self._to_entity(model), name)

Новые read-методы + DRY в репозитории

INFRASTRUCTURE

Добавлены get_by_id_with_counterparty, find_all_with_counterparty, search_with_counterparty. Построение запросов вынесено в общие хелперы _query_all / _query_search / _query_by_id — без дублирования между сущностным и read-вариантами.

ListTransactionsUseCase → find_all_with_counterparty
SearchTransactionsUseCase → search_with_counterparty
GetTransactionUseCase → get_by_id_with_counterparty
