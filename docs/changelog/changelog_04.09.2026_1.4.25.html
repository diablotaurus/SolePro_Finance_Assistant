Причина выпуска

После выпуска версии 1.4.24 были уточнены правила стартовых уведомлений Telegram-бота и проанализированы письма GitHub о неуспешных тестах. Приложение работало штатно, однако служебное сообщение о запуске отправлялось всем пользователям из списка доступа, а GitHub Actions не мог импортировать модуль резервного копирования из каталога scripts.

Границы изменений: бизнес-логика учёта, база данных, desktop-приложение, пользовательские настройки и боевой файл .env не изменялись.

Уведомление о запуске бота

Исправлено

Только администратору

  • Сообщение «Бот запущен и готов к работе» теперь отправляется исключительно в ADMIN_CHAT_ID.
  • Список TELEGRAM_ALLOWED_USERS используется только для контроля доступа к командам и больше не определяет получателей служебного уведомления.
  • Повторяющиеся сообщения на дополнительный пользовательский аккаунт устранены.
Надёжность

Безопасное отсутствие администратора

  • Если ADMIN_CHAT_ID не задан, стартовое сообщение не отправляется.
  • Запуск и polling бота продолжаются без дополнительной сетевой операции.
  • Ошибка доставки администратору по-прежнему журналируется и не останавливает приложение.

GitHub Actions

CI исправлен
  • Установлена причина двух неуспешных запусков CI для версий 1.4.23 и 1.4.24: ModuleNotFoundError: No module named 'scripts'.
  • В workflow команда pytest заменена на python -m pytest.
  • Запуск pytest как Python-модуля гарантирует добавление корня репозитория в путь импорта.
  • Тест согласованного SQLite-бэкапа получает доступ к существующему модулю scripts.backup_sqlite без изменения структуры проекта.

Архитектурные решения

Разделение ответственности

Список разрешённых пользователей отвечает за авторизацию, а ADMIN_CHAT_ID — за административные уведомления. Конфигурационные роли больше не смешиваются.

Минимальная правка CI

Структура каталога scripts и рабочий модуль резервного копирования сохранены. Исправлен способ запуска тестов, который и создавал различие между локальной средой и Linux runner.
