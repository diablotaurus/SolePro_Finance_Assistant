Обзор

Добавлены скрипты для безопасного обслуживания боевой (прод) установки: обновление кода с GitHub и резервное копирование базы данных. Прод развёрнут как копия (не git-репозиторий), а data/ — символьная ссылка на реальное хранилище БД, поэтому скрипты спроектированы максимально аккуратно к данным.

Новые скрипты

DEVOPS
scripts/update_prod.ps1 — обновление прод-версии с GitHub
scripts/update_prod.bat — обёртка (двойной клик)
scripts/backup_db.ps1 — резервная копия базы данных
scripts/README_prod.md — инструкция по использованию

Поток обновления

# Источник истины — GitHub DEV --git push--> GitHub (main) --git clone--> %TEMP% --robocopy(код)--> ПРОД
  • Бэкап реальной БД (finances.db + -wal/-shm) → .backup\db
  • Снимок текущей версии (код + конфиг) → .backup\<версия>_<дата>
  • Загрузка последнего кода из GitHub во временную папку
  • Синхронизация кода в прод (robocopy) и обновление зависимостей (py -3.13)
  • Миграции БД применяются автоматически при следующем запуске приложения

Меры безопасности

Боевые данные защищены

  • Из синхронизации исключены: .env, settings/, data (символьная ссылка), .backup/, .venv/
  • robocopy /XJ — символьная ссылка data не обходится (нет случайного захода в реальное хранилище)
  • Без /MIR — рядом с данными ничего не удаляется
  • Перед изменениями — резервная копия БД и полный снимок версии (точка отката)
  • Проверки: это прод (pyproject.toml + живой симлинк data), наличие git и py 3.13, подтверждение и напоминание закрыть приложение

Порядок использования

ИНСТРУКЦИЯ
  • Закоммитить и запушить изменения в GitHub (main)
  • Один раз скопировать scripts/ в прод-папку
  • Закрыть приложение → запустить scripts\update_prod.bat → следовать подсказкам

Подробности и параметры — в scripts/README_prod.md.
