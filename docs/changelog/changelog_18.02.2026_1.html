Подробный отчет по рефакторингу UI-настроек desktop-части и унификации работы с settings/settings.ini

Дата: 18.02.2026 Версия после изменений: 1.3.9 RC Область: Desktop / Presentation Layer Принципы: MVC, OOP, DRY, SOLID

1. Цель работ

Проблема: в окне «Статистика» часть таблиц не использовала настройки из settings/settings.ini, а логика чтения ini и применения параметров была дублирована в нескольких файлах desktop-слоя.

Цель: централизовать работу с UI-настройками, сохранить обратную совместимость и не затронуть доменный/инфраструктурный слои.

2. Архитектурное решение

  • Создан единый модуль DesktopUiSettings для чтения настроек settings.ini.
  • Создан единый конфигуратор таблиц TableUiConfigurator для применения параметров вертикального заголовка и высоты строк.
  • Рефакторинг выполнен только в presentation-слое: контроллеры, use-case, доменные модели и репозитории не изменялись.
src/solepro/presentation/desktop/ui_settings.py

3. Что изменено по файлам

  • src/solepro/presentation/desktop/views/statistics_dialog.py
    • Подключен общий сервис настроек и конфигуратор таблиц.
    • Единый механизм теперь применяется ко всем таблицам окна статистики: yearly_table, counterparties_table, concentration_table, tax_table, monthly_details_table.
    • Удалены локальные дубли чтения ini и методов применения стилей заголовков/высоты строк.
  • src/solepro/presentation/desktop/views/transaction_table.py
    • Локальные методы чтения ini заменены на общий DesktopUiSettings.
    • Применение вертикального заголовка и высоты строк переведено на TableUiConfigurator.
    • Сохранены прежние ключи и fallback-значения настроек.
  • src/solepro/presentation/desktop/counterparty_manager.py
    • Аналогично переведен на общий модуль настроек.
    • Сохранен прежний fallback по отступу высоты строки: 16.
  • src/solepro/presentation/desktop/main_window.py
    • Убран локальный дублирующий код чтения settings.ini.
    • Параметры карточек итогов (padding, spacing, background, label padding) читаются через DesktopUiSettings.

4. Соответствие принципам

  • DRY: устранено повторение однотипных методов чтения ini и настройки таблиц.
  • SRP (SOLID): View перестали совмещать ответственность за чтение конфигурации и отображение данных.
  • OCP (SOLID): новые таблицы подключаются через общий конфигуратор без копипаста.
  • MVC: изменения локализованы в представлении (presentation layer), без смешивания с бизнес-логикой.
  • OOP: поведение инкапсулировано в специализированных классах с явными обязанностями.

5. Проверки и риски

  • Выполнена синтаксическая проверка измененных файлов (AST parsing) — успешно.
  • Проверены точки входа и связанный поток desktop/telegram: RunDesktopApp.pyw, src/solepro/presentation/desktop/application.py, src/solepro/presentation/telegram/bot.py.
  • Изменения не затрагивают запуск Telegram-бота и не меняют use-case слой.
Результат: поведение UI сохранено, настройки применяются последовательно и централизованно.
Замечание: автотесты и ручной UI smoke в этом шаге не запускались; рекомендуется выполнить после мерджа.
