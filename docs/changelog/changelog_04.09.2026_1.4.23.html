Обзор релиза

Версия 1.4.23 фиксирует результат полного технического аудита проекта. Основной акцент сделан на сохранности финансовых данных, корректности миграций, предсказуемой работе desktop-интерфейса и Telegram-бота, а также на безопасной установке и обновлении прод-версии.

Важно: пользовательские .env, settings/, рабочая база в data/ и каталог резервных копий не входят в поставку и не заменяются скриптом обновления.

Данные и миграции

Безопасный переход старых баз

Целостность данных
  • Добавлено распознавание старой схемы SQLite без таблицы alembic_version.
  • Совместимая база получает базовую ревизию и последовательно обновляется до актуальной схемы.
  • Частично созданные и неизвестные схемы больше не маскируются как корректные.
  • Ошибки миграции передаются вызывающему коду как явное исключение.

Точные денежные значения

Финансовая логика
  • Денежные поля ORM переведены с двоичного Float на точный Numeric.
  • Создание и редактирование используют единое округление ROUND_HALF_UP.
  • Парсер принимает русскую запись 1.000,50 и отклоняет скрытый посторонний текст.
  • Убрано необоснованное ограничение убытка в один миллион рублей.

Транзакционность и справочники

Репозитории
  • init_db.py выполняет явные commit, rollback и освобождение scoped session.
  • Проверка уникальности контрагентов не зависит от регистра символов.
  • Интеграционный тест подтверждает миграцию старых сумм и очистку некорректных ссылок.

Desktop-приложение

Пагинация и фильтры

MVC
  • Контроллер передаёт представлению типизированный результат: страницу операций, общую и отфильтрованную статистику.
  • Навигация по страницам размещена в панели фильтров и синхронизирована с состоянием выборки.
  • Сброс фильтра больше не инициирует повторную загрузку одних и тех же данных.
  • Итоги периода считаются по всей фильтрованной выборке, а не только по видимой странице.

Экспорт и формы

Пользовательские сценарии
  • Экспорт последовательно получает все страницы выбранного периода пакетами по 1000 записей.
  • Необязательные поля описания, примечания и контакта теперь можно полностью очистить.
  • Добавлены UI smoke-тесты для пагинации, итогов и очистки полей.

Статистика

Корректность расчётов
  • Годовой рост не показывается как процент после нулевой или отрицательной базы сравнения.
  • Налоговая нагрузка и риск не рассчитываются при нулевой или отрицательной прибыли.
  • Представление получает явное неопределённое состояние вместо вводящих в заблуждение значений.

Telegram-бот

  • Добавлен отдельный постоянный лог бота, настраиваемый переменной TELEGRAM_LOG_FILE.
  • Учётные данные прокси скрываются перед записью адреса в журнал.
  • Внутренние ошибки журналируются с полным traceback, а пользователь получает безопасное общее сообщение.
  • Кратковременные NetworkError, TimedOut и RemoteProtocolError фиксируются в логе без повторяющегося спама администратору.
  • Добавлена точка запуска RunBot.pyw для desktop-сценария без лишней консоли.

Установка и обновление

Первичная установка

Windows
  • setup.bat и setup.ps1 находят Python 3.13+, создают .venv и устанавливают проект.
  • .env создаётся из примера только при отсутствии пользовательского файла.
  • Сообщения PowerShell вынесены в UTF-8 JSON, исходники скриптов остаются совместимыми с Windows PowerShell 5.1.

Резервное копирование

SQLite
  • Новый backup_sqlite.py использует штатный SQLite Online Backup API.
  • После копирования выполняется integrity_check.
  • Открытые подключения гарантированно закрываются при успехе и ошибке.

Прод-обновление

Безопасное развёртывание
  • Перед обновлением проверяются запущенные Python-процессы из прод-каталога.
  • Зависимости устанавливаются до замены файлов приложения.
  • Манифест поставки позволяет удалять только устаревшие ранее развёрнутые файлы.
  • После синхронизации обязательно применяются миграции и начальные данные.

Запуск, Docker и зависимости

  • Отладочный desktop-запуск исправлен и использует существующий scripts/run_desktop.py.
  • Docker-образ переведён на Python 3.13, запускается от непривилегированного пользователя и применяет миграции перед ботом.
  • docker-compose.yml получает секреты только из окружения, без небезопасных значений по умолчанию.
  • migrate_data.py использует корректный путь src, Decimal, детерминированное сопоставление UUID и одну транзакцию с rollback.
  • Ограничения основных версий зависимостей синхронизированы между requirements.txt и pyproject.toml.
  • GitHub Actions обновлён до актуальных основных версий действий и минимальных разрешений.
